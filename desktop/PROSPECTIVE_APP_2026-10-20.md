# 일정 입력·최근성 개인화·사전 저장 예측

작성일: 2026-10-20  
적용 범위: SleepWell 로컬 웹앱

## 구현 목적

이번 변경은 다음날 실제 생활 제약을 추천에 반영하고, 앞으로 쌓이는 자료에서 예측 오차를 소급 편향 없이 측정하기 위한 것입니다. 앱은 다음날 수면 행동을 예측하는 기능과 수면 기회를 제안하는 정책을 구분합니다. 새 기능 자체가 수면을 개선한다거나 기존 모델보다 정확하다는 결론은 아직 없습니다.

예측 대상은 계획 밤의 주수면 시작 시각과 최종 기상 시각입니다. 두 시각의 간격은 침대 체류 또는 주수면 구간에 가까우며 PSG로 측정한 총수면시간(TST)이 아닙니다. 권장 정책의 준수 여부도 건강 효과나 수면 향상 효과와 같은 지표가 아닙니다.

## 계획 밤 입력

계획 밤은 `night_id`로 식별합니다. 오후와 저녁에는 오늘 날짜가 계획 밤이고, 평소 아침 기상 전에는 전날 날짜가 현재 계획 밤입니다. 입력은 서버 시각으로 관측 시각을 찍고, 수정할 때마다 이전 버전을 덮어쓰지 않고 새 리비전으로 저장합니다.

입력 항목은 다음과 같습니다.

- 일정: 근무, 수업, 첫 일정의 시작 시각과 선택적 종료 시각
- 준비시간: 일정 시작 전에 확보할 0~240분
- 낮잠: 이미 끝난 시작·종료 구간, 한 번에 최대 240분
- 카페인: 이미 섭취한 시각과 자기보고 양(mg)

확인란을 체크하고 항목을 추가하지 않은 채 저장하면 해당 목록은 명시적인 ‘없음’입니다. 하루 입력을 저장하지 않았으면 ‘미입력’으로 남깁니다. 준비시간은 기상 후 첫 일정까지의 준비·통근·통학 시간입니다.

한 종류의 목록에는 최대 12개를 허용합니다. 미래 낮잠이나 미래 카페인, 겹치는 낮잠, 허용 범위 밖의 일정, 비정상·무한대 수치는 거부합니다. 저장된 스냅샷의 관측 시각과 리비전 번호는 추천 결과에도 그대로 보존하며, 미래 시점에 알려진 스냅샷을 과거 추천에 사용할 수 없습니다.

다음 날 시작하는 가장 이른 일정에서 준비시간을 뺀 시각이 기존 목표 기상보다 이르면 기상 제약을 앞당깁니다. 같은 날 저녁의 첫 일정을 다음 날 기상시각으로 잘못 해석하지 않습니다. 시작·종료가 있는 근무와 수업은 점유 구간으로 처리하며, 진행 중이거나 자정을 넘는 일정도 수면 가능 구간에서 제외합니다. 종료 시각이 없는 근무·수업은 목표 기상까지 이어지는 것으로 보수적으로 처리하고 경고를 표시합니다.

점유 구간을 제외한 가장 긴 연속 구간이 목표 수면시간과 입면 여유보다 짧으면 `feasible=false`와 일정 불가능 사유를 반환합니다. 이때도 취침·기상 순서와 수면 기회는 음수가 되지 않습니다. 완료된 낮잠은 Two-Process 수면압력 계산의 수면 구간에 포함합니다. 카페인은 향후 검증을 위해 저장하지만 개인별 효과를 추정한 계수가 없으므로 현재 권장 시각 계산에는 사용하지 않습니다. 입력량은 섭취 권고가 아닙니다.

## 최근성과 공백을 반영한 개인화

개인화는 가입 이후 예측 시점에 이용 가능한 첫 유효 일지 또는 연동 수면 기록부터 시작합니다. 14일을 기다리는 활성 문턱은 없습니다. 과거 아카이브는 이 신규 관측 수를 채우지 않습니다. 같은 기상일의 수정은 추천 계산 시점까지 관측된 최신 버전 하나만 사용하고, 미래 기상과 미래에 입력된 수정본은 제외합니다. `observed_at`이 없는 기존 호환 기록은 기상 시각에 관측된 것으로 취급했다는 사실을 결과에 표시합니다.

개인화가 시작된 뒤에도 누적 유효일 수는 보존합니다. 실제 계산에는 기상 후 경과일 `age`에 대해 다음 가중치를 적용합니다.

```text
record_weight = 2 ** (-age / 14)
effective_records = sum(record_weight)
personalization_weight = effective_records / (effective_records + 14)
```

따라서 14일이 지날 때마다 기록의 영향은 절반이 됩니다. 최근 기록이 많으면 개인화 비중이 증가하고, 기록을 오래 쉬면 누적 건수는 남아 있어도 유효 기록 수와 개인화 비중은 감소합니다. 가중치는 기록 입력·수정 시각이 아니라 실제 기상 시각을 기준으로 하므로 늦은 수정이 오래된 수면을 새 기록처럼 만들지 않습니다.

- 수면 위상: 최근성 가중 원형평균을 초기 위상과 혼합
- 수면 목표: 개운함 4점 이상이고 피로도 3점 이하 또는 미응답인 날이 5일 이상일 때 최근성 가중 중앙값 사용, 초기값 대비 ±30분 제한
- 입면 여유·걸음·운동: 해당 항목이 실제로 있는 기록만으로 항목별 유효 가중치와 가중 평균 계산

항목별 가중치를 분리했으므로 걸음이 한 번만 측정된 경우 전체 수면 기록 수가 많다는 이유로 그 한 값이 높은 신뢰도를 얻지 않습니다. 반환값에는 누적 유효일, 유효 가중 기록 수, 최근 14일 기록 수, 마지막 기록 공백, 항목별 유효 가중치와 계산 버전을 함께 저장합니다.

초기 수면시간은 기존과 같이 NHANES 2017–2018 성인 자료의 연령대·성별·활동 수준별 관측 수면시간 평균을 사용합니다. 이는 미국 자기보고 집단의 평균이며 개인의 최적 필요수면이나 치료 목표가 아닙니다. 지원 범위 밖이거나 충분한 집단이 없으면 사용자가 입력한 값으로 돌아갑니다. 수면 위상의 초기값은 NHANES가 아니라 사용자가 입력한 평소 취침·기상에서 계산합니다.

각성 시간상수 18.2시간, 수면 시간상수 4.2시간, 일주기 진폭 0.15는 고정값입니다. 일지 14일로 생리 상수를 식별했다고 해석하지 않습니다.

## 20시 사전 저장 예측

서버가 실행 중이면 매일 현지시각 20:00을 고정 결정 시점으로 사용합니다. 프로필, 결정 시점 이전에 관측된 수면 기록 버전, 그 시점까지 저장된 계획 밤 입력을 복제해 변경 불가능한 예측 스냅샷을 만듭니다.

- 20:00~20:15에 생성: 주 평가 대상
- 20:15 이후 처음 생성: 자료는 남기되 지연 생성으로 주 평가에서 제외
- 서버가 실행되지 않았던 과거 밤: 소급 생성하지 않음
- 한 계획 밤: 최초 예측 한 건만 저장

자동 저장을 위해서는 앱 서버가 20시 무렵 실행 중이어야 합니다. 브라우저 화면이 열려 있지 않아도 서버 타이머가 동작하지만, 서버 프로세스가 종료된 동안에는 저장할 수 없습니다.

고정 비교군은 다음 세 개입니다.

| 비교군 | 역할 |
|---|---|
| `profile_baseline` | 가입 시 평소 취침·기상과 입면 여유를 사용한 기준선 |
| `recent_adaptive` | 첫 유효 기록부터 최근성·공백 가중치를 적용한 행동 예측 모델 |
| `context_candidate` | 다음 날 일정과 준비시간을 반영하는 미검증 비교 후보 |

주 모델 표시는 `recent_adaptive`로 고정되어 있습니다. 앞으로 결과를 보고 같은 밤의 승자를 바꾸거나 과거 예측을 다시 계산하지 않습니다. `context_candidate`는 일정 정보의 추가 가치를 전향적으로 비교하기 위한 후보이며, 지금 성능 향상이 입증됐다는 의미가 아닙니다. 기존 CMI·MESA·Samsung 연구 모델을 이 사전 저장 경로에 자동 승격하지 않았습니다.

행동 예측의 일정 후보는 기상 제한을 적용하는 단순 규칙입니다. 야간 근무 등과 예상 수면이 겹치면 경고를 남깁니다. 점유 시간을 제외하는 권장 정책과 계산 목적이 다르며, 교대근무 전체를 최적화하는 모델은 아닙니다.

낮잠과 카페인은 입력 스냅샷에 보존되지만 현재 세 행동 예측군의 학습 계수에는 사용하지 않습니다. 특히 카페인 양과 수면시각 사이의 인과관계나 개인별 반응 계수를 가정하지 않습니다.

## 실제 결과 연결과 평가

예측 뒤 입력된 일지 또는 HealthKit 주수면만 평가 후보입니다. 수면 시작이 예측 생성 이전이거나, 결과가 기상 이전에 입력됐거나, 다른 계획 밤에 속하거나, 허용된 주수면 구간 범위를 벗어나면 평가에서 제외하고 사유를 남깁니다.

한 예측에 처음 연결된 실제 결과가 주 평가 결과입니다. 같은 수면을 나중에 수정하면 원래 결과를 삭제하거나 주 평가를 몰래 바꾸지 않고 수정 결과 집계에 추가합니다. 날짜가 수정돼도 이미 연결된 예측 ID를 유지해 한 수면이 두 밤의 주 평가로 중복되지 않게 합니다.

세 비교군 모두에 대해 입면 절대오차, 기상 절대오차, 두 값의 평균, 구간 길이 오차를 같은 실제 결과에서 계산합니다. 모델 버전별로만 집계하며 버전이 다른 예측을 하나의 성능처럼 합치지 않습니다. 표본이 충분히 쌓이기 전에는 보정된 불확실성 구간이나 성능 개선을 주장하지 않습니다.

이 평가는 예측 정확도 평가입니다. 추천을 따른 사람이 더 잘 잤는지, 피로가 줄었는지, 건강 결과가 좋아졌는지는 별도의 전향적 연구 질문입니다.

## 저장·내보내기·검증 상태

SQLite 변경은 기존 프로필·수면 기록·추천 테이블을 보존하는 추가형 마이그레이션입니다. 새로 저장되는 내용은 일정 입력 리비전, 계획 밤별 최초 사전 예측, 결과 평가와 수정 평가입니다. 전체 기록 내려받기에는 이 자료와 기존 변경 이력이 함께 포함됩니다. 개인 원자료를 외부 서비스로 업로드하지 않습니다.

웹앱 단위·통합 테스트 81개와 기존 연구 분석 테스트 83개, 총 164개가 통과했습니다. 여기에는 입력 경계, 자정과 야간 근무, 진행 중 일정, 미래 정보 배제, 동일 밤 단일 저장, 서버 재시작, 최초 결과와 수정 결과 분리, 기존 DB 마이그레이션이 포함됩니다. JavaScript 구문 검사도 통과했습니다. 독립된 가상 기록 DB로 입력 저장, 고정 예측 유지, 기존 수면 수정 후 최초·최신 결과 분리 표시를 브라우저에서 확인했습니다. 가상 기록 화면의 오차는 실제 사용자 성능이 아닙니다.

## 해석 제한

- 일정·최근성 개인화·사전 저장 구조가 기존 데이터 단독 또는 융합 모델보다 정확하다는 근거는 아직 없습니다.
- 권장 시각이 개인의 수면을 개선한다는 인과 효과는 아직 검증하지 않았습니다.
- 카페인은 자기보고 입력이며 현재 효과 계수나 섭취 권고에 사용하지 않습니다.
- 주수면 시작~최종 기상 구간은 TST가 아닙니다.
- NHANES 평균은 집단의 관측 수면시간이며 개인의 최적 필요수면이 아닙니다.
- 생리 시간상수는 고정값이고 개인 기록으로 새로 추정하지 않습니다.
- 기존 연구 모델은 자동으로 서비스 모델이 되지 않습니다.
