### 1. CMI 기반 S-C 모델 최종 성능평가 및 개인차 분석 (혜지)

**목표:** 수정된 S-C 모델의 sleep/wake 및 onset/wakeup 탐지 성능을 최종 확정하고, subject별 성능 차이를 확인하기.

이번 주에 완료한 CMI 전처리 및 S-C 부호 재검증 결과를 기준으로 전체 데이터에 대한 최종 평가 진행하기. 전체 ROC-AUC뿐만 아니라 subject별 ROC-AUC, PR-AUC, confusion matrix 등을 산출하고, 실제 onset/wakeup 시각과 모델이 예측한 시각 사이의 오차도 계산하기.

가능하다면 onset/wakeup MAE를 분 단위로 계산하고, 성능이 좋은 subject와 좋지 않은 subject를 각각 확인하여 `S`, `C`, `S-C score` 시계열을 함께 시각화하기.

cf. 모든 사람에게 동일한 S-C parameter를 사용하는 현재 방식에서 subject별 성능 편차가 큰지도 확인할 것. 개인별 parameter fitting이 필요한지 판단할 수 있도록 결과 정리 필요.

### 2. Sleep-EDF 수면단계 평가 파이프라인 구축 (소빈)

**목표:** Sleep-EDF를 이용하여 수면단계 예측 모델의 성능을 평가할 수 있는 공통 Ground Truth 평가 환경 만들기.

이번 주에 확정한 Sleep-EDF 30초 epoch 및 `W / N1 / N2 / N3 / REM` 라벨을 기준으로 공통 평가 코드 구축하기. 모델 예측값을 입력하면 confusion matrix, precision, recall, F1-score, macro F1, Cohen's kappa 등을 자동으로 계산할 수 있도록 정리하기.

추후 Galaxy Watch에서 제공되는 `AWAKE / LIGHT / DEEP / REM`과 비교할 수 있도록 PSG stage와 Watch stage 사이의 mapping 기준도 별도로 정리하기.

cf. PSG 평가에서는 기존 `W / N1 / N2 / N3 / REM` 5-stage 기준을 유지하고, Galaxy Watch와 비교할 때만 `N1 + N2 → LIGHT`, `N3 → DEEP` 등의 4-stage mapping을 사용할 것.

### 3. Walch wearable baseline 모델 구축 (채윤)

**목표:** Walch 데이터의 `HR + ACC + Steps`를 이용하여 실제 웨어러블 센서 기반 sleep/wake 또는 sleep stage 예측 baseline 모델 만들기.

이번 주에 재검증한 Walch 전처리 데이터를 기준으로 기본적인 머신러닝 모델을 학습시키고 성능 확인하기. 우선 Logistic Regression, Random Forest, XGBoost 등 비교적 단순한 모델부터 적용하고, 입력 feature로 HR, HR 변화량, ( ACC/activity, Steps,)  시간대 등을 사용 할 것.

평가 시 epoch를 무작위로 섞는 방식 말고, subject 단위 train/validation/test split 또는 LOSO 방식으로 진행하기

cf. 같은 사람의 데이터가 train(7)과 test(3)에 동시에 포함되지 않도록 반드시 subject 단위로 데이터 분리할 것. 이후 S-C 물리모델과 wearable 모델의 성능을 직접 비교할 수 있도록 평가 지표를 통일해서 정리하기.

### 4. Galaxy Watch 실제 데이터 표준화 및 연구용 데이터셋 제작 (혜지)

**목표:** 이번 주에 수집한 Galaxy Watch 실제 데이터를 이후 모델에 바로 입력할 수 있는 공통 데이터 형태로 변환하기.

Samsung Health Data SDK 등을 통해 확보한 `HR / Sleep / Sleep stage / Steps(주간에도 착용했을 경우)` 데이터를 timestamp 기준으로 정리하고, 연구에서 사용할 공통 schema로 변환하기.

최소한 `subject_id / timestamp / heart_rate / steps / sleep_stage / sleep_start / sleep_end / device / source` 정보를 포함하도록 하고, 가능하면 30초 epoch로 통일하기.

데이터 변환 과정에서 timezone, 자정을 넘는 수면, 중간 각성, 낮잠, HR 결측, Watch 미착용 시간, Samsung Health 내부 보정 및 device/source 중복 여부도 확인하기.

cf. 최종적으로 Galaxy Watch sleep stage는 `AWAKE / LIGHT / DEEP / REM`으로 통일하고, 원본 데이터와 전처리 데이터는 별도로 보존할 것.

### 5. 수면 분석 앱 통합하기 (채윤, 소빈)

**목표:** 사용자가 수면·활동 데이터를 입력하면 현재 수면 상태를 분석하고, 앞으로의 수면 압력과 권장 수면시간을 확인할 수 있는 실제 앱 프로토타입 만들기.

현재 제작한 프로토타입을 바탕으로 사용자가 직접 데이터를 넣을 수 있는 입력 기능을 구현하기. 입력 방식은 우선 우리가 전처리한 Galaxy Watch 및 연구 데이터를 업로드하는 방식을 기본으로 하고, 필요한 경우 최근 취침·기상 시각이나 예상 취침·기상 시각 등 기본 정보를 직접 입력할 수 있도록 구성하기.

입력된 데이터를 기존 수면 모델과 연결하여 최소한 다음 결과를 계산하고 화면에서 확인할 수 있도록 구현하기.

- 최근 수면 및 활동 기록 
- 현재 `Process S` (수면 압력)
- `Process C` (일주기 리듬)
- `S-C` 또는 sleep propensity 변화
- 앞으로의 수면 압력 변화
- 예상 또는 권장 취침 시각
- **권장 기상 시각**
- **권장 수면시간**

단순히 계산값만 수치로 보여주지 말고, 사용자가 의미를 이해할 수 있도록 그래프와 간단한 설명을 함께 표시하기. 예를 들어 수면 압력이 현재 높은지 낮은지, 어느 시간대에 잠들기 쉬워지는지 등을 직관적으로 확인할 수 있도록 구성하기.

가능하다면 사용자가 **“내일 몇 시에 일어나야 하는지” 또는 “오늘 몇 시쯤 잘 예정인지”**를 입력했을 때, 해당 조건을 기준으로 적절한 취침시간이나 수면시간을 계산해주는 기능도 구현하기.

cf. **최종 앱은 Samsung Health와 직접 연동하지 X.** Galaxy Watch와 Samsung Health는 연구 단계에서 실제 데이터를 확보하기 위한 수단으로만 사용하고, 앱에서는 우리가 정리한 데이터를 예측 모델로 사용하고, 사용자가 입력한 개인 정보(컨디션 상태, 전날 취침 시간 및 기상 시간, 갤럭시 워치 건강정보) 를 받아 분석하도록 만들 것.

### 6. 개인 장기 수면·주간 활동 데이터 전처리 및 앱 적용용 데이터셋 구축 (서윤)

**목표:** 확보한 수년간의 개인 건강 데이터에서 수면 및 주간 활동 기록을 확인하고, 이상치·결측치를 제거한 뒤 우리 앱의 장기 수면 예측 및 개인화에 사용할 수 있는 연구 데이터셋으로 구축하기.

우선 전체 데이터의 기록 기간과 구조를 확인하고, 수면 관련 데이터에서 취침 시각, 기상 시각, 총 수면시간, 수면단계 등 어떤 항목을 사용할 수 있는지 확인하기. 주간 기록에서는 심박수, 걸음 수, 활동량 등 수면 압력 및 향후 수면 예측에 활용할 수 있는 변수가 실제로 어떤 형태와 간격으로 저장되어 있는지 확인하기.

이후 timestamp와 날짜를 기준으로 수면 기록과 주간 활동 기록을 연결하고, 비정상적으로 길거나 짧은 수면, 중복된 수면 session, 비현실적인 심박수·걸음 수, 장시간 데이터 미수집 구간, 기기 미착용으로 추정되는 구간 등 이상치 및 결측치를 확인하여 전처리 기준을 정하기. 원본 데이터는 그대로 보존하고 별도의 clean dataset을 생성할 것.

전처리 완료 후 `전날 수면 → 당일 주간 활동 → 당일 밤 수면`이 날짜별로 연결되는 longitudinal dataset을 만들고, 기존 `Process S / Process C / S-C score` 계산 및 향후 24시간 수면 압력 예측 코드에 바로 입력할 수 있는 형태로 변환하기.

가능하다면 장기간 데이터를 이용해 개인의 평균 취침·기상 시각, 수면시간 분포, 평일/주말 차이, 수면 부족 누적, 활동량과 수면 변화의 관계 등 개인 baseline을 계산하고, 이를 앱의 개인화 기준값으로 사용할 수 있는지도 확인하기.

cf. 해당 데이터는 단순 모델 성능 검증용이 아니라 한 사용자의 장기간 실제 생활 데이터를 통해 개인화된 수면 예측이 가능한지 확인하는 데이터로 활용할 것. 이후 앱에서 최근 하루의 Watch 데이터만 사용하는 것이 아니라 과거 수면 history와 주간 활동 데이터를 함께 사용하여 다음날 수면 압력, 권장 취침 시각, 권장 기상 시각 및 권장 수면시간을 계산할 수 있도록 데이터 구조를 설계하기.

### 7. S-C + Wearable Hybrid 모델 구조 설계 및 1차 구현 (서윤)

**목표:** 기존 Two-Process 기반 S-C 물리모델과 wearable sensor 데이터를 결합하여 최종 연구에서 사용할 Hybrid 모델 구조 확정하기.

기존 `Process S`, `Process C`, `S-C score`를 wearable model의 입력 또는 추가 feature로 사용할 수 있도록 모델 구조 설계하기.

웨어러블 입력은 우선 `HR / activity 또는 ACC / Steps / 시간대`를 기본으로 하고, 물리모델에서 계산된 `S / C / S-C` 값을 추가하여 기존 wearable-only 모델과 성능을 비교할 수 있도록 하기.

최소 비교 구조는 아래와 같이 설정하기.

- S-C 물리모델
    
- Wearable-only 모델
    
- S-C + Wearable Hybrid 모델

이후 현재 시점까지의 수면 history와 wearable 데이터를 입력하여 향후 24시간의 `Process S`, `Process C`, sleep propensity를 계산할 수 있는 구조까지 설계하기.

cf. 최종적으로 Hybrid 모델 결과가 **다음날 수면 압력, 권장 취침 시각, 권장 기상 시각, 권장 수면시간** 계산으로 이어질 수 있도록 입력값과 출력값을 명확하게 정의할 것.

### 8. 공통 데이터 구조 및 평가 코드 통합 (서윤)

**목표:** CMI / Sleep-EDF / Walch / Galaxy Watch / 개인 장기 데이터를 하나의 공통 연구 파이프라인에서 사용할 수 있도록 데이터 구조와 평가 방식을 통합하기.

각 데이터셋마다 별도의 코드와 변수명을 사용하는 것을 최소화하고, 공통적으로 사용할 수 있는 데이터 schema 및 evaluation function을 확정하기.

공통 데이터에는 가능한 범위에서 `subject_id / timestamp / sleep_wake / sleep_stage / heart_rate / activity / steps / source` 형태를 사용하고, 데이터셋에 존재하지 않는 값은 결측값으로 처리하기.

평가 함수도 sleep/wake, sleep stage, onset/wakeup, subject-level 평가로 구분하여 동일한 코드에서 데이터셋만 변경하여 사용할 수 있도록 정리하기.

개인 장기 데이터의 경우에는 추가적으로 날짜별 sleep history와 주간 활동을 연결할 수 있도록 `date / previous_sleep / daytime_activity / current_sleep` 관계가 유지되도록 설계할 것.

cf. 이후 모델 성능 비교표와 최종 발표자료를 만들 때 각 데이터셋의 평가 기준이 달라 결과를 다시 계산하는 일이 없도록 이번 단계에서 평가 규칙을 확정할 것.

### 9. 학술제 중간 발표자료 1차 제작 (채윤, 혜지, 소빈)

**목표:** 지금까지 진행한 연구와 현재 개발 중인 앱의 방향을 하나로 정리하여 중간 발표자료 초안 만들기.

미리캔버스나 캔바에서 **하나의 공동 캔버스**를 만들고, 전원이 같은 발표자료 안에서 작업하기. 각자 약 2~3장 정도를 담당하되, 개인별 발표자료처럼 따로 만들어 붙이는 방식이 아니라 전체 연구 흐름 안에서 자신의 담당 내용이 자연스럽게 이어지도록 구성하면 좋음. **현재 제작 중인 수면 예측 앱 프로토타입은 발표자료에 넣지 말 것.**

전체 발표자료의 흐름은 가급적 다음 순서를 유지하기.

`연구 배경 및 문제 정의 → 연구 목표 → 데이터 수집 및 전처리 → 개인 데이터 수집 현황 → 앱 프로토타입 현황(시각 자료 첨부 X)


페이지마다 제목·폰트·색상·그래프 형식 등 기본 디자인을 공동 작업으로 동일하게 맞추고, 같은 개념을 사람마다 다르게 표현하지 않도록 용어도 통일할 것. 각자의 실험 결과는 가능한 경우 설명만 적지 말고 **그래프, 모델 구조도, 데이터 예 등 시각자료를 함께 사용하기.**

이번 주에는 발표자료를 만들고, 다음주 중 확인해서 자연스럽게 이을 예정.

## 별도 공지

**Galaxy Watch 실제 착용 데이터:** 현재 확보한 데이터에 이어 가능하면 팀원별 데이터를 추가 수집하여 실제 사용자 간 차이를 확인할 것. 단, 연구 참여자의 데이터를 사용할 경우 데이터 공유 범위 및 비식별화 기준 확인 필요.

**개인 장기 데이터:** 수년치 데이터는 단기 Galaxy Watch 테스트 데이터와 별도로 관리하고, 원본/전처리본/모델 입력용 데이터를 분리하여 보관할 것. 개인식별 가능 정보가 포함되어 있는지도 사전에 확인 필요.
