# 수면 분석 앱 통합 — 채윤·소빈 합의안 (초안)
**작성자:** 채윤 | **작성일:** 2026-09-24 | **상태:** 소빈 확인 후 확정

---

## 1. 합의 배경
- 이번 주 목표: 입력 → 전처리 → 분석 → 결과 화면까지 한 번에 이어지는 앱 프로토타입 뼈대
- 기능 고도화가 아니라 **흐름이 끝까지 한 번 돌아가는 것**이 기준
- 모델은 아직 확정되지 않았으므로, 이번 주는 **구조만 잡고** 모델 확정 후 연결
- 통합 = 채윤(백엔드·전처리)과 소빈(프론트·결과 화면)이 각자 만든 기능·모듈·시각화가 하나로 돌아가게 하는 것

---

## 2. 전체 흐름 (합의된 기준)

```
[사용자]
  │
  ├─ CSV 업로드 (삼성 헬스 수면 단계 CSV → sleep_stage_cleaned.csv 형식)
  │     ↓
  │  [채윤: 백엔드 / 전처리]
  │     ① CsvFileSource.kt로 CSV 파싱 → SleepSession 목록
  │     ② SleepSession → 30초 epoch 변환 (isSleep true/false)
  │        ⚠️ 주의: 세션 사이 깨어 있던 시간까지 포함한 전체 타임라인으로 구성
  │           (수면 구간만 넣으면 사이를 전부 수면으로 계산해 S가 틀어짐)
  │     ③ Kotlin으로 옮긴 Two-Process 계산 함수 호출 (임시 모델, 약 20줄)
  │        → S, C, propensity 계산 (과거~현재). 파라미터는 코드 기본값.
  │        → "임시 모델"로 표시. futureS·권장 시각은 아직 없음 → "준비 중"
  │     ④ 분석 결과(AnalysisResult) 생성 → 소빈(프론트) 직접 전달
  │     ↓
  │  [업로드 직후 백그라운드 계산 완료. 결과 화면 진입 시 바로 표시]
  │
  ├─ [소빈: 프론트 / 결과 화면]
  │     ⑤ 최근 수면 기록 표시 (전체, SleepSession 기반 그래프)
  │     ⑥ 현재 S, C, propensity 수치 + 그래프 (계산 30초, 그래프 10~15분 간격)
  │     ⑦ 미래 수면 압력 변화 → "준비 중" (또는 서윤 언니 정의 후 반영)
  │     ⑧ 권장 취침·기상 시각, 권장 수면시간 → "준비 중" (서윤 언니 담당)
  │     ⑨ (선택) 목표 기상/예정 취침 입력 → 변경 시 재계산
  │
  └─ 연구자 화면: 30초 epoch·수면 그래프·export (기존 기능 유지)
```

## 3. 만나는 지점 합의 (핵심)

### 3-1. 전처리 결과 형식 — 채윤 → 소빈

**전송 데이터:** `List<SleepSession>` (또는 이에 준하는 DTO)

**SleepSession 최소 구성:**

| 필드 | 형식 | 설명 |
|---|---|---|
| `sessionId` | String | UUID |
| `startMs` | Long | 세션 시작 (KST epoch ms) |
| `endMs` | Long | 세션 종료 (KST epoch ms) |
| `stages` | List<StageSegment> | 단계별 구간 목록 |

**StageSegment:**

| 필드 | 형식 | 설명 |
|---|---|---|
| `startMs` | Long | 구간 시작 (KST epoch ms) |
| `endMs` | Long | 구간 종료 (KST epoch ms) |
| `stage` | Enum/String | WAKE / N2 / N3 / REM (또는 0/1/2/3) |

**합의 사항 — 소빈 답변 확정:**
- stage 표현 방식: **AWAKE / LIGHT / DEEP / REM 문자열**. (N2로 매핑하지 않음. md: "워치 단계는 AWAKE/LIGHT/DEEP/REM으로 통일, PSG와 비교할 때만 매핑")
- 전송 형식: 같은 Kotlin 앱 안 → **객체 직접 전달**. 별도 직렬화 불필요.
- 데이터 범위: **모델 = 최근 7일**(S 시작값 확보를 위해 며칠치 연속 기록 필요), **기록 화면 = 전체**.

### 3-2. 모델 입력·출력 형식 — 소빈 ↔ 채윤

**모델 입력 (채윤 → 모델):**
```
EpochInput:
  timestampMs: Long   // 30초 간격, KST epoch ms
  isSleep:     Boolean // 수면 중이면 true
```
→ `sleep_stage_cleaned.csv`의 stage 구간을 30초 epoch로 분할하여 생성
→ 사용자 직접 입력(취침·기상 시각)도 동일 형식으로 변환하여 포함

**모델 출력 (모델 → 채윤 → 소빈):**
```
AnalysisResult:
  currentS:            Float       // 현재 Process S (0~1)
  currentC:            Float       // 현재 Process C
  currentPropensity:   Float       // 현재 S-C score / sleep propensity
  sleepRecords:        List<SleepRecord>   // 최근 수면 기록 요약
  scHistory:           List<PropensityPoint>  // 과거~현재 S·C·propensity 시계열
  futureS:             List<PredictedPoint>   // 향후 24시간 S 예측 시계열
  recommendation:
    recommendedBedTimeMs:  Long?
    recommendedWakeTimeMs: Long?
    recommendedSleepMin:   Float?
```

**합의 사항 — 소빈 답변 확정:**
- 모델 호출 시점: **CSV 업로드 직후 백그라운드 계산**. 사용자 조건 변경 시 재계산.
- 모델 없는 항목 처리: **"준비 중" 표시**. 임시값 사용 시 **"임시 모델(분석 화면 출력 확인 정도)"**라고 명시.
- futureS 그래프 간격: **계산은 30초 촘촘히, 전달·그래프는 10~15분 간격**.
- 입력 타임라인: **세션 사이 깨어 있던 시간까지 포함된 전체 타임라인**. 수면 구간만 넣으면 사이를 모두 수면으로 계산해 S 오류 발생.
- 권장 시각·futureS 담당: **서윤 언니(모델 쪽)**. 이번 주 MVP는 앱 쪽 임시 배치 → 서윤 정의 후 교체.

### 3-3. 데이터 전달 방향 요약

```
채윤 → 소빈:
  1. List<SleepSession>          (수면 기록, 그래프용)
  2. AnalysisResult              (모델 분석 결과, 결과 화면용)

소빈 → 채윤:
  1. 직접 입력 데이터 (취침·기상 시각, 목표 기상·예정 취침 — 선택)
  2. CSV 파일 자체 (업로드 시)
```

## 5. 확인·결정 필요 사항 (팀장 포함)

| # | 항목 | 확정 내용 |

| 4 | 모델 없는 항목 처리 | **"준비 중" 표시**. 임시값 사용 시 "임시 모델" 명시 |

### 5-2. 팀장·서윤언니 확인 필요 (일부 소빈 제안 포함)
| # | 항목 | 내용 / 소빈 제안 |
|---|---|---|
| 1 | 권장 시각 계산 담당 | **서윤 언니(모델 쪽)**. 이번 주 MVP는 앱 쪽 임시 배치 → 서윤 정의 후 교체 |
| 2 | Light → LIGHT 4단계 표기 | **변경 확정**: N2 매핑하지 않고 LIGHT로 표기 (md 기준: 워치 단계 AWAKE/LIGHT/DEEP/REM 통일) |
| 3 | Two-Process 공용 코드 사용 | **사용 확정**: S·C·propensity 계산 부분만 **Kotlin으로 옮겨 임시 모델**로 사용 (약 20줄). 모델 입력 별도 형식 불필요 |
| 4 | 심박·걸음 원본 CSV | **혜지에게 따로 문의** (이번 주 회의 때 언급) |

### 5-3. 확인 완료됨 (공유된 문제)
- 앱 시간대 오류: 에뮬레이터 UTC → 수면 시각 9시간 앞당겨 표시, night 값 하루 어긋남 → 수정 예정 (소빈)
- Two-Process 코드 pandas 3.x 마이크로초 문제: S 값 변화 거의 없음 (2시간 수면 후 기대 0.31 → 실제 0.4998) → 팀장 공유 완료

## 6. 통합 테스트 계획

**목표:** 전처리 결과 → 앱 → 결과 화면까지 한 번에 동작 확인

**시나리오:**
1. `sleep_stage_cleaned.csv` 업로드 (테스트용 샘플)
2. CsvFileSource 파싱 확인 → SleepSession 정상 생성
3. 30초 epoch 변환 확인 → **전체 타임라인(세션 사이 WAKE 포함)**으로 isSleep 정상 부여
4. Kotlin 임시 모델(S·C·propensity 계산) 호출 확인 → S, C, propensity 값 정상
5. 결과 화면: 수면 기록 그래프(전체), S·C·propensity 표시(10~15분 간격), futureS·권장 시각 "준비 중" 표시 확인
6. 시간대 오류 수정 여부 확인 (KST 기준 시각 표시)
7. 사용자 조건(목표 기상·예정 취침) 변경 시 재계산 동작 확인

**통합 테스트 일정:** 개별 작업 완료 후 같이 진행 (팀장 답변)

## 7. 앞으로의 수면 압력 변화·권장 시각 관련 메모

현재 Two-Process 공용 코드(또는 이를 Kotlin으로 옮긴 임시 모델)는 **과거 기록의 S·C·propensity만 계산**하고, 다음 기능은 없음:
- 앞으로의 수면 압력 변화 예측 (futureS)
- 권장 취침 시각
- 권장 기상 시각
- 권장 수면시간

→ 이 기능들은 **서윤 언니(모델 쪽) 담당**.
→ 이번 주 MVP: 앱 쪽에 **임시 배치**, "준비 중"으로 표시. 서윤 언니 정의가 나오면 교체·맞춤.
→ 파라미터는 코드 기본값 사용, 확정값이 아니므로 "임시 모델"로 표시.
