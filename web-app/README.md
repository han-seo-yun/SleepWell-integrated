# SleepWell · 지금 사용하는 로컬 웹앱

## 연구 모델 업데이트 (2026-10-10)

MESA ACT·Walch·개인 Samsung·NHANES의 연구용 학습과 비교 평가를 완료했습니다. [데이터 분할·실제 성능 보고서](../docs/RESEARCH_RESULTS_2026-10-10.md)를 참고하세요. 모델과 개인별 데이터는 저장소 밖 `연구용데이터/`에 보관합니다. MESA/Walch는 센서 구간 분류 모델이므로 아래 `--forecast-model`의 일지 기반 미래 예측 계약과 다릅니다. 이번 연구 모델을 웹 권장 정책에 자동 적용하지 않았으며, 10월 9일 연구 현황 snapshot은 새 실험 결과를 자동 반영하지 않습니다.

## Windows 및 MESA 점검 연결 (2026-10-09)

저장소 루트에서 `python -X utf8 web-app/server.py --mesa-inventory docs/MESA_INVENTORY_2026-10-09.json`을 실행하고 http://127.0.0.1:8765 를 엽니다. Windows용 `Start-SleepWell.ps1`도 추가했습니다.

**연구 현황** 메뉴는 가입 전에도 MESA 집계·표본 QC·모델 상태를 보여줍니다. `--forecast-model PATH`로 검증된 일지 기반 경량 JSON을 연결할 수 있습니다. 10월 9일 snapshot 당시에는 MESA 학습 모델이 없었으며, 데이터 업로드가 자동 학습·성능 향상을 뜻하지 않습니다.

- [데이터 활용 가능성·단계별 계획](../docs/MESA_WEB_PLAN_2026-10-09.md)
- [모델 계약·실행·검증·제한사항](../docs/WEB_MESA_DELIVERY_2026-10-09.md)

`Start-SleepWell.command`를 더블 클릭하면 http://127.0.0.1:8765 를 엽니다.
현재 Mac에서 Python 3.11 환경과 기존 연구 자료 연결을 확인했습니다.
서버가 종료되어도 `.local/sleepwell.sqlite3`의 기록은 남습니다. 외장 디스크 T9를 연결한 상태에서 실행하세요.

## 사용 흐름

1. 별명, 나이, 생활 유형, 평소 수면·활동 평균, 목표 기상, 목표 수면시간을 입력합니다.
2. 기존 Samsung 자료가 본인 자료라면 **기존 본인 자료 연결**을 체크합니다. 학생 집단 평균으로 취급하지 않습니다.
3. 첫날부터 권장 취침·기상 시각, 이유, 수면압력 곡선을 제공합니다.
4. 다음날 완료된 수면과 개운함·피로도, 기상일의 걸음·운동을 기록합니다. 미측정은 빈칸으로 둡니다.
5. 시작 후 14일 경과 **및 최근 28일 내 유효 관측 14일**을 모두 충족하면 개인화합니다. 과거 아카이브를 불러온 날짜는 신규 관측일로 세지 않습니다.
6. 이후 기록할 때마다 개인화값과 추천을 갱신합니다. 데이터가 부족해지면 초기값 모드로 돌아가며 화면에 표시합니다.
7. `전체 기록 내려받기`로 프로필, 기록, 추천 당시 설정, 변경 이력을 JSON으로 백업합니다.

## 구현된 개인화

- 처음 2주: 자기보고 생활 평균 + 물리모델의 기본 상수. 자료 연결 시 과거 본인 활동 평균, 최근 30회 수면 위상을 참고합니다.
- 과거 위상은 현재 자기보고 75%, 과거 원형평균 25%로 초기화합니다. 이 가중치는 아직 검증 전 운영 규칙입니다.
- 개인화 전환 후: 최근 28일 관측과 초기값을 `n/(n+14)`로 섞습니다. 일주기 위상, 입면 여유, 활동·운동 기준을 갱신합니다.
- 개운함 4점 이상이고 피로도 3점 이하(또는 미응답)인 날이 5일 이상이면 해당 수면시간 중앙값을 목표에 반영합니다. 초기 목표 대비 ±30분으로 제한합니다.
- τ각성=18.2h, τ수면=4.2h, 일주기 진폭=0.15는 아직 고정입니다. 이 값들을 14일로 추정했다고 주장하지 않습니다.
- 활동·운동 평균은 생활 기준 및 이후 연구 입력으로 저장하며, 수면 필요량으로 직접 환산하지 않습니다.

## 추천 목표 및 연구 모델 연결

목표는 **수면 개선을 위한 일정 제안**입니다. 다음날 기상 제약과 수면 기회 확보를 우선하고, 그 주변 30분 후보에서 Two-Process S/C와 규칙성을 비교합니다. 최근 수면 부족에 따른 수면 기회 확대(최대 30분)는 검증 전 정책입니다.

기존 `미래예측모델/causal_sleep_timing_forecast.py`와 저장된 시간순 개발 구간으로 행동 예측 모델을 메모리에 재구성합니다. 테스트 데이터로 재학습하지 않습니다. 연결한 본인 프로필에서는 20시 이후 보조 예상 시각을 보여줍니다. 당일 시계열 센서가 없는 웹 입력은 학습 중앙값 대치가 필요하므로 원래 평가 성능이 적용되지 않습니다. 이 예상 행동을 권장 시각의 정답으로 사용하지 않습니다.

현재 시간대는 Asia/Seoul 고정입니다. 교대근무·다상수면·수면장애 치료용 일정 최적화는 구현하지 않았습니다. 직접 입력 수면은 입면/각성 미입력 시 침대 체류시간을 사용하므로 수면시간을 과대 추정할 수 있습니다.

## 저장과 운영

로컬 1인 프로필입니다. 인터넷 회원가입·다중 사용자 인증·서버 업로드는 없습니다. 서버는 `127.0.0.1`에만 바인딩되어 다른 기기의 iPhone Safari에서 이 주소로 연결할 수 없습니다. iPhone 센서 자동 연동은 별도 `ios-app` 프로젝트에 있습니다. 웹앱 기록과 iOS 앱 저장소는 현재 자동 동기화되지 않습니다.

프로필을 다른 사람으로 바꾸면 기존 기록과 섞이므로 **동일인의 설정 수정**으로만 사용하세요. 추천은 생성 시각, 정책 버전, 입력 해시, 당시 설정·상수를 보존합니다. 취침 전에 만들어진 추천만 다음날 기록과 비교하며 준수 오차를 효과 지표와 구분합니다.

전체 백업 JSON을 정기적으로 다른 안전한 위치에 보관하세요. DB 파일은 Git에서 제외되고 원본 연구 파일은 수정하지 않습니다. JSON 복원 UI, 알림, HealthKit 자동 가져오기, 피드백 효과의 통계 검정은 후속 작업입니다.

## 실행 / 검증

```bash
cd web-app
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python server.py
.venv/bin/python -m unittest discover -s tests -v
```

추천 기본 경로는 표준 라이브러리로 실행 가능합니다. pandas/pyarrow/scikit-learn/lightgbm은 기존 개인자료·연구 모델 연결에 필요합니다. 의존성 또는 원본 자료가 없으면 자체 입력 추천만 사용합니다.

일반적인 연령별 수면 권고의 참고: [CDC About Sleep](https://www.cdc.gov/sleep/about/index.html). 앱의 상한·가중치·2주 전환 기준은 임상적으로 검증된 규칙이 아니라 이 프로젝트의 초기 설계입니다.
