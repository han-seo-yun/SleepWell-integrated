# SleepWell — 2주 실행 계획 및 4인 업무 분담

작성일: 2026-10-10 · 기간: 팀 착수일을 D1로 하는 14일 · 책임자: 서윤

최신 역할 수정: 혜지는 기존 설문·성능 실험과 PCR 확장·문헌·후속 데이터 조사를 함께 맡는다. 소빈·채윤은 소프트웨어화를 공동 담당한다. 아래 두 사람의 세부 분업은 충돌 방지를 위한 제안이며, 서윤의 최종 모델 통합 책임은 유지한다.

이 문서는 최신 역할 합의를 반영하며 이전 `sleepwell-four-person-next-phase-2026-10-10.md`의 역할 배정을 대체한다. 현재 확인한 코드·실험 보고·파일 목록에 근거한 실행 계획이다. 중간보고서 HWP 원문 전체를 검토했다는 뜻은 아니다. 이 문서 작성으로 신규 데이터 정제·재학습·팀원 전송·배포가 완료된 것은 아니다.

## 1. 2주 뒤 무엇을 완성할 것인가

**현재 데이터를 재현 가능한 연구용 데이터로 관리하고, 설문 추가의 효과를 검증하면서, 예측과 권장을 구분하는 실행 가능한 웹 소프트웨어를 만든다.**

- 주 산출물: 연구 데이터/QC 명세, 설문 추가 실험 보고서, 권장 정책·모델 연결 명세, 로컬 실행 가능한 웹앱 패키지, 시연영상, PCR 확장 타당성 보고서.
- 웹 우선. 기존 수집은 전원 계속하되 iOS/Android 신규 개발이나 센서 자동 연동은 이번 필수 범위에서 제외한다.
- 성능이 반드시 좋아져야 성공인 것은 아니다. 개선되지 않은 원인과 재현 결과도 유효한 연구 성과다.
- 질병 예측의 임상 검증, 인터넷 다중 사용자 서비스, 추천의 인과적 수면 개선 입증은 2주 완료 목표가 아니다.

## 2. 역할: 각자 산출물을 끝까지 책임진다

## 4. 정규화·이상치 처리·전처리 재사용 기준

작업 순서는 **원본 보존 → 버전 고정/QC → 사람·시간 분할 → Train으로 전처리 적합 → Validation 선택 → 고정 Test 평가**다.

### 4.1 삭제보다 판정 근거와 기록을 먼저 남긴다

1. 원본·기존 전처리는 덮어쓰지 않는다. 파생 데이터에 QC 사유와 버전을 남긴다.
2. 완전히 같은 중복 행, 스키마 위반, 무한대, 판독 불가능한 시간, 단위 확인 후의 불가능한 값은 규칙에 따라 제외 또는 격리한다. 충돌하는 중복은 임의로 하나를 고르지 않는다.
3. 짧거나 긴 수면, 높은 심박, 낮은 활동을 그 자체로 오류로 취급하지 않는다. 실제 특이 행동·질환 신호일 수 있다. “6~9시간 밖은 삭제” 같은 일괄 기준을 사용하지 않는다.
4. IQR/MAD 등은 우선 이상치 **표시**에 사용한다. 클리핑/강건 변환은 Train에서 정하고, 미처리 대비 민감도 분석을 남긴다. Test 오차가 크다는 이유로 해당 사람·날짜를 삭제하지 않는다.
5. 결측/비착용과 실제 0을 구분한다. 보간은 미래 관측을 사용하지 않는 조건에서만 검토한다. 설문 무응답·모름·거절 코드를 0점으로 만들지 않는다.
6. 표준화/중앙값 대치/분위수 경계/학습 기반 prior는 Train에만 fit한다. Validation/Test에는 같은 변환을 적용한다. 트리 모델은 무조건 표준화하지 않고 필요성을 검토한다.
7. 제외 전후 사람 수·행 수·관측시간·집단별 비율을 보고한다. 필터 기준과 커버리지 기준은 성능 확인 전에 고정한다.

### 4.2 서로 다른 데이터를 같은 숫자로 만드는 것만으로 통합되지 않는다

- 시간대, 날짜 경계, 수면 시작/종료 정의, 센서 epoch와 물리 단위를 먼저 통일한다. 취침은 날짜를 포함해 저장하며 자정 전후 시각을 단순 선형 평균하지 않는다.
- 걸음, MESA activity count, ENMO, MIMS는 서로 다른 관측량이다. 이름을 `activity`로 바꾸어 직접 합치지 않는다. 코호트·장치별 특징과 출처를 유지한다.
- NHANES 조도 합계는 유효 측정 분모를 확인해 환산한다. 손목 조도를 눈에 도달하는 빛이나 melanopic 자극과 동일시하지 않는다. 상한 처리 정보도 보존한다.
- **PCR/S/C 방정식에는 물리 단위가 유지된 입력**을 전달한다. 학습용 z-score 심박·조도를 생리 방정식에 그대로 넣지 않는다.
- 서로 다른 연구의 동일 숫자 ID를 같은 사람으로 결합하지 않는다. 보조 참고표는 독립 집단의 prior 후보이지 개인 정답이 아니다.
- 기존 CMI 미래 구간 기반 `sc_score`, MMASH의 사후 기상시각 유래 특징 등 누수 위험 입력은 재사용하지 않는다. 이미 생성한 보수적 연구용 버전을 출발점으로 사용한다.
- 정규화는 빠진 질병 라벨, 한국 사용자 대표성, 추천 효과의 정답을 만들어 주지 않는다.

산출물: 데이터 사전, 원본·출력 hash와 버전 manifest, QC 집계, 제외/격리 사유표, 고정 split, Train 전처리 설정, 재현 명령, known-limitations 문서.

## 5. 혜지 실험: 설문이 추가되면 좋아지는가?

### 먼저 확인할 조건

실제 팀 설문 응답의 위치·문항·척도·응답 시각·참가자 연결키·사용 동의를 D1에 확인한다. 이번 제한적 파일 목록 검사에서 팀 설문 응답 파일을 특정하지 못했으므로 이미 확보되었다고 가정하지 않는다. NHANES 설문은 팀 설문과 별개다.

미래 취침/기상을 평가하려면 **결정 시점 이전 설문과 이후 실제 수면 기록이 같은 사람·날짜에 연결**되어야 한다. 일회성 “평소 수면시간”만 있으면 횡단면 분석은 가능하지만 다음 날 예측의 성능 향상을 입증할 수 없다.

### 서로 다른 질문을 분리한 실험

| 실험 | 고정할 것 | 바꿀 것 | 결과 |
|---|---|---|---|
| A. 사람 수 증가 | 모델/특징/평가 집단/전처리 절차 | Train 사람의 중첩 25/50/75/100% 표본 | Validation 학습량 곡선, 표본 수와 변동 |
| B. 설문 특징의 이득 | 같은 사람·날짜·분할·정답 | 기본 이력 vs 기본 이력+설문 | 두 모델의 paired 오차 차이 |
| C. 개인 이력 누적 | 동일한 예측 시점 및 미래 평가 구간 | 사용 가능한 과거 이력 길이 | 기록량·커버리지별 오차, 개인화 가능 조건 |

- 표본 수가 충분할 때 사전 지정한 3개 seed 등으로 반복한다. 4명 파일을 행으로 나누어 수천 명 규모처럼 평가하지 않는다.
- 집단 간 일반화는 사람 단위 분리, 동일인의 미래 예측은 시간순 분리로 각각 보고한다. 중첩된 입력 창과 정답 경계의 누출도 확인한다.
- 기존 Train/Validation/Test 소속은 유지한다. 신규 batch는 별도 버전으로 관리하며 기존 평가 대상을 Train으로 옮기지 않는다. 학습량 비교는 동일한 고정 Validation으로 한다.
- 이미 본 기존 Test는 탐색적 재평가로 표시한다. 새 최종 평가 구간은 결과를 보기 전에 동결하고 최종 선택 후 한 번 평가한다.
- 단순 중앙값/최근 유효 이력 기준선을 포함하고 일지-only와 센서 결합 모델을 분리한다.
- 주지표: 취침/기상 MAE(분), 수면시간 MAE(분), 참가자 수·유효 밤 수·커버리지. 시각 오차는 날짜·자정 처리를 포함한 정의를 사전 고정한다. 불확실성은 사람 또는 시간 블록 구조를 반영한다.
- 센서 **epoch(30/60/120/300초)**와 학습 반복 횟수를 구별한다. 기존 비교를 먼저 재사용하고, 새 반복 수는 Validation으로 선택한다. 신경망을 쓰지 않으면 boosting iteration을 신경망 epoch라고 부르지 않는다.
- 결과는 개선/차이 불명확/악화 모두 보고한다. 응답 추가마다 사용자 서비스 모델을 자동 재학습·교체하지 않는다.

표본·정답이 부족하면: 파이프라인 재현 + 실제 관측 n의 파일럿 결과 + 추가 수집 필요량/조건을 제출한다. 두 주 데이터만으로 장기 개인화 효과를 입증했다고 쓰지 않는다.

## 6. 서윤 설계: 예측 모델을 어떻게 권장시간으로 연결할까?

**관측 정리 → 행동 예측 및 생리 상태 시뮬레이션 → 생활 제약을 적용한 권장 정책 → 화면 표시**로 경계를 나눈다.

| 계층 | 질문 | 결과와 책임 |
|---|---|---|
| 행동 예측 | 현재 입력에서 실제로 언제 잘/깰 가능성이 있는가? | 예측 시각·사용 입력·모델 버전·예측 가능 여부. 혜지 실험, 서윤 선정 |
| 생리 시뮬레이션 | 가정한 수면·빛 조건에서 S/C 또는 PCR 상태가 어떻게 변하는가? | 관측/가정 구분, 초기조건·상수·민감도. 서윤 설계, 혜지 문헌 지원 |
| 권장 정책 | 목표 기상, 가능한 취침 범위, 목표 수면 기회에 맞춰 어떤 일정을 제안할까? | 권장 취침/기상/수면 기회, 이유·제약 충돌·fallback. 서윤 |
| 웹 표현 | 무엇이 예측이고 무엇이 제안이며 얼마나 근거가 있는가? | 서로 다른 카드, 상태·정책 버전·근거 부족 안내. 소빈 |

관측된 나쁜 수면 습관을 잘 맞혔다고 그 시각을 권장하지 않는다. “권장 수면 기회”와 “실제 측정 수면시간”도 구분한다. 입면·중간각성 정보가 없으면 침대 체류시간을 실제 수면시간처럼 표시하지 않는다.

웹 기본 입력만으로 실행 가능한 계약을 먼저 만든다. 현재 MESA/Walch 센서 분류 모델이나 개인 센서 결합 모델을 일지 기반 `forecast_model.py`에 바로 넣지 않는다. 호환 모델이 없으면 기존 명시적 규칙/S/C fallback을 유지한다. 임의 JSON 변환으로 비호환 모델을 지원한다고 주장하지 않는다.

통합 명세에는 입력명·단위·시각/입수 가능 시각·결측·특징 순서·필수 센서, 출력명·시간대·모델/정책 버전·연구 상태·fallback 이유를 넣는다. 동일한 고정 합성 입력에 대한 연구 코드와 웹 출력의 허용 오차는 구현 전에 고정한다. 미래 빛/행동은 관측처럼 쓰지 않고 가정으로 표시한다.

현재 앱은 14일 경과와 최근 28일 내 유효 관측 14일을 함께 요구하는 개인화 규칙이 있다. 개발 시연용 합성 경과일을 실제 사용자 데이터처럼 속이지 않는다. 권장 준수 오차와 다음 날 개운함은 기술적으로 모니터링하되 추천 효과의 인과 추정으로 해석하지 않는다.

## 7. 소빈·채윤: 웹앱을 실행 가능한 소프트웨어로 만든다

상세 공동 인계서는 같은 폴더의 `SOBIN_SOFTWARE_HANDOFF_2026-10-10.md`를 사용한다. 기존 링크를 보존하기 위해 파일명은 유지하되 내용은 소빈·채윤 공동 담당으로 갱신했다.

이번 “소프트웨어화”는 **로컬 설치·실행·설정·저장·복구·테스트·설명서가 갖춰진 연구용 웹 소프트웨어**를 의미한다. 별도 데스크톱 프레임워크, EXE 포장, PWA, 클라우드 다중 사용자화는 필수로 추가하지 않는다. 기존 실행기를 보완하는 방식이 우선이다.

- 기존 `web-app/`의 서버·UI·실행기를 재사용하고 연구 PC의 고정 절대경로 의존성을 설정으로 분리한다.
- 연구 데이터가 없어도 합성 데모 또는 직접 입력으로 실행되어야 한다. 모델 미탑재·비호환·결측을 정상 상태로 안내한다.
- 입력 검증, 자정·날짜 경계, 저장 후 재시작, 오류 안내, 백업을 검증한다. 복원 기능은 기존 자료 덮어쓰기 방지와 테스트까지 가능할 때 포함하고 미구현이면 명시한다.
- 초기 모드/개인화 조건 미충족/연구 예측/권장 정책을 구분하고 모델·정책 버전을 표시한다.
- 기본 바인딩은 기존 `127.0.0.1`을 유지한다. 인증 없는 서버를 외부 공개하지 않는다. 로컬 1인 프로필을 인터넷 회원가입 서비스로 설명하지 않는다.
- 공개 저장소·배포 ZIP·영상에는 실제 설문, 원본, 개인별 예측, DB, 토큰, 식별 가능한 기록을 포함하지 않는다.
- 서윤은 모델 경계·어댑터와 최종 통합 승인, 소빈은 화면·사용 흐름·영상, 채윤은 서버·저장·설정·실행 패키지·서버 테스트를 담당한다. 공동 소프트웨어 산출물은 두 사람이 함께 검증한다.

## 8. 혜지: PCR 및 질병 관련 확장 조사 병행

기존 채윤의 연구 조사 역할을 혜지가 함께 맡는다. 업무 과부하를 피하기 위해 설문·데이터 실험을 우선하고, PCR은 핵심 문헌 3~5편과 후보 최대 2개의 타당성 확인을 필수 범위로 한다. 추가 문헌·합성 시뮬레이션은 여유가 있을 때 수행한다.

현재 `E:/학술제/물리모델/pcr.py`에는 수면/일주기 생리 시뮬레이션 프로토타입이 있다. **이미 전신 질병 예측 모델이 구현된 상태가 아니다.** 코드의 파라미터 출처·기본값 차이·빛 입력 가정과 초기조건 민감도를 문헌과 대조한다.

Hong 등의 CSS 연구는 교대근무자의 일주기/수면 조화와 주관적 졸림의 연관성을 다룬다. 질병 진단 검증으로 확대 해석하지 않는다. [Hong et al., 2021, iScience](https://pmc.ncbi.nlm.nih.gov/articles/PMC8479255/)

### 후보는 최대 2개만 깊게 조사

| 후보 | 필요한 정답·시점 | 현재 판단 |
|---|---|---|
| PSG AHI 기반 수면무호흡 부담의 탐색적 스크리닝 | 동시 PSG AHI/QC, 같은 사람의 이전/동시 입력, 사전 정의한 AHI 기준 | ACT 파일만으로 라벨 확보를 가정할 수 없음. 현재 질병 진단이나 미래 발병 예측으로 부르지 않음 |
| 기준시점 이후 심혈관 사건 위험 | 기존 질환 여부, 사건 종류/시각, 추적·중도절단·사망, 사건 이전 수면 입력 | 별도 종단 자료·권한 필요. 생존분석/보정/외부 검증을 검토할 후속 과제 |

MESA의 전향 연구는 1,992명·111건의 심혈관 사건을 분석했다. 수면과 질병의 연관성을 뒷받침하지만 현재 로컬 ACT 자료에 사건 라벨이 있다는 뜻도, 개인 추천의 인과 효과를 입증한다는 뜻도 아니다. [MESA sleep regularity/CVD 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC7237955/)

D14 산출물: 핵심 문헌 3~5편 비교표(대상/입력/라벨/성능/한계), 실제 보유·미보유 변수 구분, 후보 최대 2개의 대상·정답·예측 시점·기간·평가·권한표, 진행/보류 결론. 자료가 없으면 “라벨 확보 전 보류”가 타당한 완료 결과다. 합성 입력 PCR 시뮬레이션은 선택 산출물이며 질병 성능 평가로 쓰지 않는다.

MESA 관련 자료는 제공 경로와 승인 범위를 먼저 확인한다. 공식 MESA 접근 안내에는 승인된 연구계획과 DMDA가 요구되며, BioLINCC와 다른 제공처의 조건이 같은 것은 아니다. NSRR 등을 통해 받은 자료는 해당 DUA를 별도로 확인한다. 본 계획은 재배포 허가를 대신하지 않는다. [MESA 접근 정책](https://mesa-nhlbi.org/researchers/registration), [BioLINCC MESA 자료 범위](https://biolincc.nhlbi.nih.gov/studies/mesa/)

### 권장 전달 방식

| 받는 사람 | 기본 전달물 | 전달하지 않아도 되는 것 |
|---|---|---|
| 혜지 | 최소 모델용 표, 변수 사전, QC·split·manifest, 실험 코드/설정 + PCR 코드/가정·라벨 가용성 표·문헌/데이터 접근 경로 | 전 센서 원본·전 코호트·모든 개인 예측, 목적/권한이 미확정인 질병 원본 |
| 소빈 | UI 소스, 합성 예제, 모델/API 계약, 집계 상태·표시 문구 | MESA 개인별 원본, 실제 설문, 개인 연구 DB |
| 채윤 | 서버 소스, 합성 예제/DB, 설정·실행 명세, 모델/API 계약, 승인된 호환 모델 산출물(권한 확인 후) | MESA 개인별 원본, 실제 설문, 개인 연구 DB |
| 서윤 | 원본·전체 연구 산출물의 관리와 별도 안전한 백업 | 공개 Git/바탕화면 동기화 폴더에 원본 복제 불필요 |

1. **기본안은 중앙 데이터 + 코드 인계다.** 권한이 불명확하면 혜지는 합성 데이터로 코드·설정을 개발하고 서윤의 통제된 환경에서 검토 후 실행한다. 이 계획은 원격 접속이나 외부 서버를 자동 개방하지 않는다.
2. 실제 데이터 전달이 허용된 경우만 목적에 필요한 컬럼·대상·기간을 최소화해 기관 승인된 암호화 저장/전송 수단으로 전달한다. 가명 ID도 개인정보·재식별 위험에서 자유롭지 않다.
3. manifest에는 버전, 출처·사용 범위, 파일 hash, 행/사람 수, 단위, 라벨 종류, 분할, 결측/QC, 생성 코드 버전, 필수 실행환경, 승인 수신자·보관/폐기 기준을 넣는다. 개인 ID 대응표와 원본 경로 등 민감 manifest는 공개 Git에서 제외한다.
4. 수신 측은 hash·스키마·수량과 소규모 재현 테스트를 확인한다. 연구 모델 pickle/joblib은 신뢰된 내부 산출물만 로드한다.
5. 승인된 표 하나가 필요하면 그 표만 넘긴다. 작은 모델 파일이라고 해서 웹 계약에 맞거나 배포 허가가 있는 것은 아니다.
6. 데이터가 추가되면 새 snapshot/hash를 기록한다. 읽는 동안 변경된 파일은 재시도/격리하고 기존 결과의 입력 버전을 소급 변경하지 않는다.

바탕화면은 현재 OneDrive 연결 경로이므로 **계획서·인계서 사본만** 둔다. 원본·개인 설문·모델용 개인 자료는 이 문서 복사 작업에 포함하지 않는다.

| **D3~4** | 권장 정책·fallback 명세, 모델 어댑터 경계 구현 | 필요한 표 정제·Train 전처리·snapshot, PCR 보유/미보유 라벨 표 | 입력/오류/저장 UX, 합성 결과 화면 | 경로 설정·실행기·저장/백업·서버 오류 처리 | QC·분할 누출 검사, 고정 합성 입출력 테스트 |
| **D5~7** | 기준선·일지-only·생리 특징 조합 판단, 계약 리뷰 | 학습량/설문/반복별 Validation 실험, 핵심 문헌 비교 초안 | 예측·권장 분리·상태/버전 화면, 사용자 흐름 테스트 | API·저장 회귀 테스트, 실행 패키지 초안 | **D7 중간 점검:** 재현 가능한 기준선·실행 가능한 앱·문헌 근거 |

지연 시 우선순위: P0 기존 앱 안정 실행·계약·데이터 QC·정직한 결과 → P1 호환 예측 통합·설문 실험 → P2 신규 질병 모델/EXE/PWA. P2 때문에 P0를 미루지 않는다. 통합 가능한 모델이 없으면 명확한 fallback을 가진 소프트웨어와 미승격 근거를 제출한다.

## 11. 완료 판정과 검증

- 데이터: 원본 불변, QC 사유·제외량·split·hash 존재. 신규 전처리의 Train-only 적합과 미래 정보 차단을 테스트로 확인한다.
- 실험: 기준선, 표본 수, 평가 대상·버전, 사전 고정된 Validation 선택, Test 열람 여부, 불확실성·악화 결과가 모두 보고된다. 개선 수치만 발췌하지 않는다.
- 모델/앱: 합성 고정 입력에서 연구 출력과 웹 출력의 허용 오차 충족. 모델 없음/잘못된 버전/결측에서도 명시적 fallback 또는 예측 불가가 나온다.
- 소프트웨어: 기록 후 재시작 보존, 잘못된 입력 처리, 연구 원본 없이 실행, 설명서만으로 재현, 테스트 결과와 남은 결함 목록이 있다.
- PCR: 각 주장에 원문 근거, 실제 미보유 라벨·권한·검증 한계, 다음 연구의 진행/보류 근거가 있다.
- 보고/영상: 연구용·비진단 문구, 예측과 권장 구분, 실제 데이터와 합성 시연 구분, 개인식별정보 미노출을 전원이 확인한다.

프로젝트 문서·코드 검토는 현재 실제 파일을 근거로 했으며, 위 완료 기준은 앞으로 수행할 작업이다. 이번 수정 대상은 이 실행 계획과 소빈·채윤 공동 인계 문서이며, 코드 구현·팀원 메시지 전송은 포함하지 않는다.
